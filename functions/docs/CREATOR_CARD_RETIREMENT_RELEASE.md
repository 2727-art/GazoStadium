## 変更

- トップのカード枠・初回取得・60秒ポーリング・10秒切替・操作イベントを撤去。
- カード編集・PNG生成・共有・ストア案内・プレミアム販売と専用CSSを撤去。
- 初期化・正式対戦・重複結果確認・市場成約のカード成長同期を撤去。
- `economyAction` の旧公開・削除操作と旧商品購入は、データを変更する前に終了応答を返す。
- RTDBの `topMessages`、`topMessageOwners`、`topMessageEntriesByUser` はクライアントの読み書きを閉鎖。管理用履歴・購入記録・所有情報は保持。
- ランキング・ランキングの公開設定・実績展示・名場面カード・牧場の管理人カードは維持。

## 返還

ユーザー承認済みの方針は、旧 `feature_top_message` 購入者へ500 Payずつ返還。
RTDBの所有情報とFirestoreの購入記録を照合し、片方だけに残る購入者も対象にする。
Firestore transactionでウォレットと台帳を同時更新し、`creatorCardRetirementRefund` に返還済み額を記録する。
再実行・同時実行・途中失敗後の再開で二重返還しない。既存の購入・装備・実績は変更しない。
残高と予約入金の上限で入らない分は権利を残し、後のウォレット確認で受け取る。
通常ユーザーの初期化に購入照会などの通信は追加しない。

2026-10-28 14:27 JSTの読み取り確認: 対象30人、返還予定15,000 Pay、上限による保留0 Pay。この時点では未変更。

## 配備手順

1. `npm --prefix functions run check` を通す。
2. カード更新の到達経路を含むFunctions (`economyAction`, `valueMarketAction`, `playerSafetyAction`, `cleanupPlayerSafety`) を配備する。
3. RTDB RulesとHosting、Cloudflareの公開資材を配備する。
4. `node functions/scripts/refund-retired-creator-cards.cjs --project gazostadium` で再確認する。
5. 同じコマンドに `--apply` を付けて返還する。標準の管理認証またはFirebase CLIのログインを利用する。認証情報を出力・保存しない。
6. 読み取り専用で再実行し、返還済み人数と残額を確認する。
7. `node functions/scripts/verify-creator-card-retirement-release.cjs` で4公開経路のHTMLと変更資材がコミットに一致すること、管理用ファイルが404であることを確認する。
