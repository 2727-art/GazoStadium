# 通常型1on1の候補失効時の自動復帰修正

候補ルームの失効確認が一度失敗したり「処理中」を返したりした後、ルームが削除されると、旧フロントは復帰タイマーを失い、1.5秒ごとに `permission_denied` を表示して次の相手を探せなくなっていた。

候補ごとに監視・定期取得・失効／復帰タイマー・確認中の通信・入室処理を管理する。読み取り拒否、失効通知、タイムアウトでは、まず監視と定期取得を停止し、既存の `soloSessionAction: expire` で確認する。

- サーバーが `active` を返した場合は同じルームへ入室し、成立済みの対戦を失効扱いにしない。
- `expired` / `destroyed`、または現在のセッションに属する候補が存在しない応答の場合は、候補を解除して再検索する。
- `offered`、通信失敗、不明な応答の場合は候補を保持し、20秒後に再確認する。1.5秒ごとの拒否ルーム取得は再開しない。
- 通信失敗の案内は復帰中に一度だけ表示する。想定内の候補失効は英語エラーを表示しない。
- 同時に届く通知は確認通信・入室を共有する。世代、状態オブジェクト、候補監視オブジェクトで旧応答を除外する。
- 停止・画面離脱・入室時に候補の監視と再試行を解除する。遅延した旧応答で新しい検索を解除しない。
- 非表示・オフラインで自動再検索が一時停止している場合は、通信を開始せず復帰タイマーを保持する。表示・接続が戻ると再試行できる。

公開変更は `online.js` と `index.html` のモジュールキャッシュキー `solo-offer-recovery-v1`。バックエンド、Database Rules、戦略型、ランキング仕様、内部RATEに変更はない。Hostingとmain連携Workersへ公開し、Functionsの再デプロイは不要。
