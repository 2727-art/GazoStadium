# お貢ぎ牧場：払った請求が残り二重に払えた不具合の修正（2026-10-26）

## 見つけた経緯

ユーザーの依頼「同時に色々と牧場の修正をしたので、不具合が発生しそうな部分を先回りして検証」で、独立したコードレビュー（別のエージェント、読み取りのみ）と、ローカルの Firebase エミュレータで2人のプレイヤーを動かす通しの操作を行った。

エミュレータの通しで、財布が請求を払ったあとも、その請求が両方の画面の「未払いの請求」とタイムラインの印に残った。契約の記録を読むと、払った請求の鍵が `pendingRequests` に残っており、同じ5 Payの請求を2回払えた（レシート2枚、財布が2回減った）。コードの読み取りだけのレビューでは見つからなかった。

## 原因

契約の書き込み（`flush`）が `transaction.set(..., { merge: true })` だった。本物の Firestore では `merge: true` は入れ子の地図を深く混ぜるので、`pendingRequests` から鍵を消した地図を書いても、消した鍵は残る。牧場の開始（2026-10-01）からある。単体テストの Firestore の偽物は最上位の欄だけを混ぜていた（地図を丸ごと置き換えた）ため、テストは通っていた。

影響: 払った・取り消した請求が「未払いの請求」に残る、3件の上限に数えられて請求できなくなる、同じ請求をもう一度払える。

## 対応内容

- `flush` の契約の書き込みを `mergeFields`（書いた最上位の欄を丸ごと置き換える）にした。地図の欄は、どの操作も今の値を広げた丸ごとの地図を渡している（偽物を本物と同じにしても、牧場のテストがすべて通ることで確かめた）
- 牧場のテストの Firestore の偽物3つを、本物と同じ混ぜ方（`merge: true` は深く混ぜる、`mergeFields` は欄ごと置き換える）にした（`functions/test/helpers/firestore-merge.cjs`）
- 回帰テスト: 払った・取り消した請求が保存された契約から消え、同じ請求の2回目は「その請求は残っていません」で断られる（偽物）。本物の Firestore（エミュレータ）でも同じ確認を `tribute-cost-emulator.test.js` に足した。どちらも修正前のコードでは失敗し、修正後は通る
- 修復スクリプト `functions/scripts/repair-tribute-pending-requests.cjs`: 既定は読み取りのみで、進行中・申込中の契約に残った請求と、全部の契約の二重払い（同じ請求への献上が2回以上）を数える。`--apply` で、出来事から「払った・取り消した・断った」と分かる鍵だけを消す（`updatedAt` には触れない）

レビューの指摘から、あわせて直したもの（画面のみ）:
- 申し込み画面に、管理人の宣言（未払いは既読無視・スクショを載せる）と「高額請求」の札が出ていなかった（申し込み先を作る時に一部の欄しか写していなかった。宣言の機能の公開時からの取り残し）
- 財布がスクショ掲載の許可を外しても、管理人のスクショ表示が続いた → その場で終える
- 呼び名の保存・スクショ表示の切り替えで、打ちかけのメッセージが消えた → 残す
- やりとりの切り抜き画像に、請求の一言がそのまま入った（契約後の一言は連絡先なども書けるようになったため）→ カードと同じ判定を通った一言だけを入れる

## 残っていること

- 二重払いの返金（7回・130 Pay、終わった契約2件）をするかは、ユーザーが決める。受け取った管理人からは、手数料5%が消却された残りが入っている
- 今回は直していないもの: 契約の画面は最近動いた40件まで（40件を超える管理人では、古い申し込みが「やること」に出ないことがある）、スクショ表示でも献上の印や出来事の行の財布名・残高報告は残る、呼び名を付けた時に同じ財布のほかの行は読み直すまで変わらない
- 牧場以外のモード（AnjuPayフリマなど）のテストの偽物も最上位の欄だけを混ぜているので、同じ種類の不具合が隠れている可能性がある（今回は調べていない）
- 本番での牧場の操作（実際の支払い・取り消し）は確認していない（エミュレータで確認）
