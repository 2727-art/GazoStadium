# トップ・通常1on1・戦略型1on1 貼り合いデザイン改修（2026-09-30）

## 対応内容

「艶っぽい舞台」だった見た目を、ユーザーが承認した見本（DMの密室 × 採点メーター、暗い基調のまま）に置き換えた。ゲームのルール・点数計算・報酬・通信の形式は変えていない。

- 実装コミット: `f7c98b9`（origin/main）
- トップ: 幕・スポットライト・カードの扇を廃止。見出し「貼って、刺して、点で返す。」とやりとりの見本、通常1on1の入口、「いま入れる卓」（通常・戦略型・自由卓の募集札。待機・対戦・卓数は実数を自動更新）、「ほかの遊び方」。既存の一覧は見出しを「記録と道具」に変更
- 通常1on1: 公開・採点・結果をDMの吹き出しで表示。1〜10点のボタンがメーターを兼ね、帯（1〜6 まだ平気／7〜8 効いた／9〜10 刺さった）はリアクションと同じ区切り。結果は採点した側の吹き出しで点数とひとことを返す。VS・FINISH・試合結果も同じ見た目へ
- 戦略型1on1: 手・点数・権利・答えを吹き出しで表示し、点数には70〜100点のメーター（目印の位置＝理性へのダメージ）。90点以上の権利は「質問／指示」タブで選ぶ。読みメモはノート風で開閉を保持し、PCではスレッドについてくる
- フォント: 見出しに Dela Gothic One、読みメモに Yomogi（Google Fonts）
- localhost で `?strategyPreview` を付けた時だけ、Firebaseにつながずに戦略型の対戦画面を確認できる見本を追加（送信・チャットは実行しない）

## 配信対象

- Hosting のみ: `index.html`（フォントとキャッシュキー `hariai-dm-v1`）、`app.js`、`online.js`、`strategy.js`、`velvet.css`、`velvet-battle.css`、`strategy.css`
- Functions、Realtime Database Rules、Firestore は対象外

- `npm run check` 相当（Node.js 24.15.0）: **1,599件中1,574成功・失敗0・25スキップ**（スキップはエミュレータ専用）。トップの配置テスト2件を新しい構成に合わせて更新し、`hariai-dm-design.test.js` を追加
- 見本画面（`?battlePreview`・`?strategyPreview`）で、スマホ幅（320px・390px）とPC幅（1280px）の各画面を確認し、ページの横はみ出しがないことを確認した
- ローカルの Auth／Database／Firestore／Functions／Hosting エミュレータで、別オリジンの2プレイヤーが対戦した
  - トップ: 募集札の待機人数が、相手の待機に合わせて通常・戦略型それぞれ1人に更新された
  - 通常1on1: 新しい「この卓に入る」から入室して対戦。公開・採点（下書きの吹き出し、メーター、口調のリアクション）・結果（採点した側の吹き出し、勝った組の縁取り、ダメージ）・2ラウンド目の採点ログ・FINISH・試合結果（WIN／LOSE）まで進んだ
  - 戦略型1on1: 「本式で挑む」から入室し、ペルソナ・デッキ封印・正体公開を経て対戦。78点（手番交代）、91点（権利＋連投、「指示」タブで語尾♡を選択 → 相手が承諾 → 連投2手目）、72点（連投ボーナス込みで理性−7）を実行し、吹き出しの左右・メーターの位置・読みメモの値を確認。降参で決着し、最終の弱点照合を通って両者の結果画面に「対戦スレッドを見返す」が同じ吹き出しで表示された
  - 両タブともスクリプトエラーなし
- エミュレータには AnjuPay 台帳設定の文書がなく、試合結果の確定が止まったため、エミュレータの Firestore にだけ `systemConfig/anjuPayLedger` を作って続行した（本番には書き込んでいない）

## 本番反映結果

- `f7c98b9` を origin/main へ push した直後に Hosting を公開した。新規アップロードは7ファイル（上記の配信対象と一致）
- 手元の見本用サーバー設定（`.claude/`、コミット対象外）は、公開の間だけ作業フォルダの外へ移した
- web.app・firebaseapp.com・anjugames.workers.dev の3経路で、`index.html` と6ファイルが手元と一致し、`README.md`・`STRATEGY_HARIAI_DESIGN.md`・`functions/docs/`・`.claude/launch.json`・`functions/test/` は404だった（36項目、初回で全一致）

- 本番では対戦画面を開いておらず、実対戦も行っていない（匿名アカウント作成と本番戦績への記録を避けるため）

## 互換性と限界

- 本番の HTML と静的ファイルは `Cache-Control: max-age=3600` のため、公開前にページを読み込んでいた人は、最大1時間ほど旧画面、または旧いHTMLと新しいスクリプト・スタイルが混ざった見た目になりうる。通信の形式と保存するデータは変えていないため、対戦・記録への影響はない
- iPhone／Android 実機、Safari での確認は行っていない
- 全画面共通のサイトのロゴ（明朝体・金色）は今回の対象外で、そのまま
